Badge

A badge flags a fixed property in a word, such as the belt panel's Moves the belt warning. It is never interactive and never carries live state.

Overview

A badge is a short, uppercase, non-interactive label with a dot that marks a property of the thing beside it. Stride Link uses exactly one: the warning badge Moves the belt in the header of the belt controls panel in mock set A.

  • Use a badge to flag a fixed property of a panel or row that the reader must notice before acting.
  • Do not use a badge for live state: the status line and the verdict carry state, in words, through a polite live region.
  • Do not use a badge as a button or a filter; it has no interactive states.

Mocks only. Set A shows the badge in all 25 of its belt-panel states; set B and the shipped page have no badge. The shipped kit does not include the badge CSS.

Anatomy

  1. Dot0.375rem circle in currentColor, decorative; the word carries the meaning.
  2. Label--text-overline: 12 px bold, uppercase, --letter-spacing-wide.
  3. ContainerPill (--radius-full), 22 px tall, --space-2 inline padding, tone background.

Variants

Five tones share one shape. Tone follows the meaning of the label, never decoration: warning is for things that can cause harm, such as a moving belt.

OfflineProposedUnlockedMoves the beltSilent
Neutral (no modifier), info, success, warning, danger. Only warning appears in the mocks.

The starter kit's solid and count badges are not part of this system: no screen uses them, and the solid label (ink on --color-info-solid) is 3.57:1 in light, below the 4.5:1 text minimum.

Sizes

One size: 22 px tall (min-height: 1.375rem), 12 px label. Badges are never touch targets, so the 44 px floor of L2-061 does not apply.

States

A badge is static text. It has no hover, focus, active or disabled state: it is never focusable and never reacts to the pointer. The matrix shows that each tone looks the same whatever the pointer does.

Responsive behaviour

  • Badges never truncate (white-space: nowrap); keep labels to three words.
  • In a .panel__header the header wraps (flex-wrap: wrap), so below about 360 px the badge drops under the panel title instead of squeezing it.
  • Size does not change with the breakpoint.

Theming

Two component tokens, --badge-bg and --badge-fg, alias the status -bg and -fg tokens. In dark the backgrounds become deep tints (--palette-amber-950 for warning) and the text lightens to the 300 steps, so each pair stays above 9:1.

.badge--warning { --badge-bg: var(--color-warning-bg); --badge-fg: var(--color-warning-fg); }

Accessibility

Role and pattern

Plain inline text in a <span>; no ARIA role. Screen readers read the word in reading order, after the panel title. Do not add role="status": the badge does not change.

Keyboard

KeyAction
NoneBadges are not focusable and are skipped by Tab (L2-060 applies to controls only).

Focus

Never receives focus. If a badge ever needs to explain more, put the explanation in visible text next to it, not in a tooltip.

Labelling

The visible word is the whole message; the dot is a CSS pseudo-element and is not announced. Colour is never the only signal (L2-062): “Moves the belt” reads the same in greyscale.

Motion

None.

Touch

Not a target. Nothing is hidden behind hover.

Content

  • Uppercase is applied by CSS; write the label in sentence case in the HTML (Moves the belt) so screen readers do not spell it out.
  • Say the consequence, not a category: “Moves the belt”, not “Danger” or “Warning”.
  • Three words at most.
