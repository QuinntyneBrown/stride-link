Device list

The nearby-treadmill rows of the browser's Bluetooth chooser, drawn in both mock sets for flow context only.

Overview

The device list is the list of nearby treadmills inside the browser's Bluetooth chooser. The chooser belongs to Chrome or Edge, not to Stride Link: its look and wording are the browser's. Both mock sets draw it only to show the flow from Connect to a connection (L2-006, L2-009). The list is documented so that mocks of the flow stay consistent; it is never built in the product.

  • It appears only after a Connect press (L2-006). Filters: names starting STRIDE, Stride or stride, or the Echelon service; names starting ECH, Ech or ech are excluded.
  • Choosing a row and Pair resolves requestDevice(); Cancel rejects with NotFoundError and the page shows No treadmill selected. (L2-009).
  • See Dialog for the chooser frame and Spinner for the scanning line.

Anatomy

  1. Device iconBluetooth glyph, muted, aria-hidden.
  2. Device nameAs the device advertises it, inserted as text (L2-051).
  3. SignalCaption, muted, pushed to the end of the row.
  4. RowA full-width button, 44 px minimum, aria-pressed for the chosen row; rows are separated by hairlines.

Sizes

One size: rows are at least 44 px tall (--target-min) with 16 px inline padding.

States

VariantDefaultHoverFocusSelected
Row

Scanning and empty states are lines in the chooser body, not rows: “Scanning for devices…” with a spinner, and “No compatible devices found.” (both sets). Set A adds “Make sure the treadmill is on and not connected to another app or phone.” under the empty line.

Both themes

Responsive behaviour

  • The list fills the chooser body; long names wrap and the signal stays at the end of the row.
  • On phones the browser shows its own full-screen chooser; the mock's bottom-sheet framing is an approximation.

Theming

Rows use --color-bg-surface-raised, hover --color-bg-subtle, selected --color-accent-subtle. The real chooser ignores page tokens; these only keep the mocks coherent in both themes. The .native class switches to the system font so the drawing reads as browser chrome, not as Stride Link.

Accessibility

Role and pattern

In the mocks: a list of toggle buttons (aria-pressed) inside a dialog. The browser's real chooser exposes its own listbox; Stride Link cannot change it.

Keyboard

KeyAction
Tab / Shift+TabMoves between rows, Cancel and Pair (mock behaviour).
Enter, SpaceSelects a row.
EscCancels the chooser: NotFoundError, then “No treadmill selected.”

Focus

Set B puts initial focus on Cancel, set A on Pair. When the chooser closes, focus returns to Connect.

Labelling

The row's name and signal form its accessible name. Device names are untrusted: they are inserted as text, so a name like <img src=x onerror=alert(1)> shows literally (L2-051).

Motion

None.

Touch

Rows are 44 px tall and full width.

Content

  • Device names are shown exactly as advertised; the cast uses STRIDE-8S, STRIDE-8S-4F2A, STRIDE4-2C1F, STRIDE4-2C91.
  • The chooser title is the browser's: set B “This file wants to pair”, set A “quinntynebrown.github.io wants to pair” (hosted copy). Neither is Stride Link copy.
