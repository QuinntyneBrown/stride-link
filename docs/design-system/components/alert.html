Alert

A tinted box for something that happened and changes what to do next. Shipped once, for connection lost.

Overview

An alert is a tinted box that reports something that happened and changes what the tester should do next. The shipped page has one: connection lost, shown at the top of the first column when the link drops while a run is active (L2-012), with a Dismiss button. Both mock sets also use alerts under the status line for connection errors, with set A adding a title.

  • Use an alert when the tester must act or must know something to stay safe.
  • Use the status line for a phase or for an error the next Connect press fixes. In the shipped page, every connection error lives there and not in an alert.
  • Use a toast (mocks) for a passing confirmation that needs no action.
  • Use the Stop bar's own error for a failed Stop.

Anatomy

  1. Icon (mocks)20 px, --alert-icon, aria-hidden. The shipped alert has none.
  2. Title (set A).alert__title, --text-label.
  3. Text.alert__text, the L2 message.
  4. Actions (optional).alert__actions: inline links or text buttons in the alert colour.
  5. Accent edge4 px left border in --alert-border on a --alert-bg tint.

Responsive behaviour

  • Text wraps beside the Dismiss button. Known shipped quirk: .alert is a flex row with the default align-items: stretch, so on a phone the Dismiss button stretches to the height of the wrapped text (shown above). Recommended system fix: .alert > .btn { align-self: flex-start; }.
  • The shipped alert sits at the top of app__primary, above the status panel, so it is first in reading order at every width (L2-064).
  • The banner (set B) spans the viewport under the top bar and centres its content.

Theming

Four component tokens per tone, --alert-bg, --alert-fg, --alert-border and --alert-icon, alias the status tokens, so dark mode needs no alert rule.

.alert--danger { --alert-bg: var(--color-danger-bg); --alert-fg: var(--color-danger-fg); --alert-border: var(--color-danger-border); --alert-icon: var(--color-danger-icon); }

Accessibility

Role and pattern

The WAI-ARIA alert role: an assertive live region. The shipped connection-lost alert is hidden until needed, then its text is set and it is shown, so it is announced once at once. Use role="alert" only for safety messages; set B's info and warning alerts sit inside a polite region and need no role.

Keyboard

KeyAction
TabReaches Dismiss or the action link in reading order.
Enter, SpaceDismisses (shipped) or follows the action.

Focus

Showing an alert never moves focus. Gap in the shipped page: Dismiss hides the alert while the button has focus, and nothing moves focus afterwards, so it falls back to the document body. Recommended: move focus to Connect after Dismiss. Raised as a finding, not changed here.

Labelling

The text is the message. Icons are aria-hidden; the tone is never the only signal, because each message names the problem in words (L2-062).

Content

  • Connection lost (L2-012), verbatim: Connection lost. If the belt is moving, use the treadmill's stop button or safety key.
  • Error text is the L2 string; never shorten it to a title alone.
  • Set A titles (Connection timed out, Turn on Bluetooth, Bike rejected, Echelon service missing, Couldn't subscribe, Unsupported browser, Open the hosted copy, Stop the belt by hand) are mock copy, not L2.
  • Action text says where it goes: “Open the hosted copy”, not the raw URL (set B shows the URL as the link text).
