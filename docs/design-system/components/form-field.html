Form field

The wrapper every input uses: label, control row, help, and the L2 error message after an invalid apply.

Overview

The form field is the wrapper every input uses: a visible label, the control row, a help line and, when needed, an error line. It owns the spacing between those parts (--space-1) and the aria-describedby wiring. In Stride Link it wraps the two belt inputs; the belt-gate checkbox is its own pattern (see Checkbox).

  • Label above the control, never beside it and never a placeholder.
  • Help is always visible and states the accepted range.
  • The error appears only after the tester presses the apply button with an invalid value, and disappears on the next valid apply (shipped belt-panel.ts).

Anatomy

  1. Label.field__label, --text-label, linked with for.
  2. Control rowInput plus apply button (.control-row).
  3. Help.field__help, body-sm, muted; first id in aria-describedby.
  4. Error.field__error, body-sm, danger text with a ⚠ prefix; second id in aria-describedby; role="alert" when shipped.

Variants

The field has one layout. Its variants are the two inputs it wraps.

Sizes

One size; the field takes the width of its grid cell. Spacing between parts is fixed at --space-1 (4 px), and fields in the belt controls are --space-5 apart.

There is no submitting state: the frame is queued at once (L2-056) and the outcome is logged, so the field returns to default immediately. There is no disabled state: when the gate is unticked the whole field is removed (L2-042).

Responsive behaviour

  • Below 576 px fields stack in one column; from 576 px the belt controls grid places speed and incline side by side.
  • Help and error wrap within the field; nothing truncates at 320 px.

Theming

The wrapper reads --color-fg-default (label), --color-fg-muted (help) and --color-danger-fg (error), plus the component token --field-gap (--space-1). Both themes come from the semantic tokens; there is nothing to override per theme.

Accessibility

Role and pattern

Native label plus input. aria-describedby lists help then error, so a screen reader reads the range before the problem. The shipped error paragraph has role="alert", so it is announced when it appears after an apply.

Keyboard

KeyAction
TabLabel is skipped; focus goes input, then apply button.
Enter / Space on the buttonValidates and applies; on error focus stays on the button and the alert announces the message.

Focus

Focus is never moved programmatically on error: the tester stays where they are and hears the alert.

Labelling

Label text equals the accessible name (L2-063). Required state is not shown because there is nothing optional: every apply needs a value.

Motion

No motion; the error appears without animation.

Touch

Tapping the label focuses the input; input and button are 44 px tall (L2-061).

Content

  • Errors are fixed by L2-046 and L2-047, character for character: Speed is capped at 3 km/h for the smoke test., Enter a speed from 0 to 3 km/h., Enter a whole-number incline from 0 to 15.
  • Help is product copy: 0 to 3 km/h, in steps of 0.1 and Whole numbers from 0 to 15 (shipped and set B; set A omits the comma in the speed help).
  • Labels name the value and unit: Target speed (km/h), Target incline.
