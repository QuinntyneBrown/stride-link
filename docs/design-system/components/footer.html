Overview

The footer is the last landmark on the page. It identifies the build: product name, version and commit, stamped by scripts/build.ts (L2-068). A tester attaching an exported log to a bug report can quote it.

  • Shipped: Stride Link followed by the version and commit in monospace, filled into #build-version and #build-commit at build time.
  • Set A adds a privacy line; set B adds a protocol-provenance line. Neither ships.
  • No links: there is nowhere to go.

Anatomy

  1. Build identityProduct name plus version and commit in .mono.
  2. Secondary line (mocks only)Wraps to the next row on narrow screens; pushed to the end from wider widths (justify-content: space-between).

Sizes

One size: body-sm text, 32 px vertical padding (--space-8), --layout-margin sides, capped at the 1140 px container plus margins.

States

Static; no interactive states. While the belt is active the body's bottom padding keeps the footer above the fixed Stop bar (shipped: bar height plus --space-2).

Responsive behaviour

  • Items wrap onto separate rows at narrow widths (flex-wrap: wrap, 16 px gap).
  • From 992 px the footer is centred under the two-column layout with the same 1140 px cap.
  • The commit hash may wrap; it never forces horizontal scroll.

Theming

Reads --color-fg-muted text and a --color-border-default top rule; links inside (none today) would inherit the muted colour.
