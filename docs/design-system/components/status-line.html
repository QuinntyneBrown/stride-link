Status line

One polite live sentence that says what the page is doing now, with a dot that is never the only signal.

Overview

The status line is one sentence that says what the page is doing now: checking Bluetooth, connecting, sending init, waiting, connected, disconnected, or why something failed. It is the page's single aria-live="polite" status region (L2-063), so every change is announced once without moving focus.

  • Use it for the current phase of the run and for errors that block the next step.
  • Use the verdict for the outcome of a run; it has its own polite region.
  • Use an alert under the status line (mocks) when an error needs a title, a link or a longer explanation.
  • Never use it for telemetry: speed, incline and heart rate are not announced (L2-063).

Shipped: the status line has no tone modifier and the dot is always the neutral --color-fg-subtle; the words alone carry the state. Both mock sets add tone modifiers (status--busy with a pulsing dot, --success, --warning, --danger), and both use status--neutral or status--idle, which no stylesheet defines; they fall back to the neutral dot.

Anatomy

  1. State dot10 px circle in --status-dot, aria-hidden. Decorative: the sentence carries the state.
  2. Status sentence--text-body-lg at semibold, --color-fg-default; the live text.
  3. Detail (optional, set A).status__detail: --text-body-sm muted, pulled up by --space-2. Outside the live region in set A.

Sizes

One size. The sentence is 18 px (--font-size-lg) so it reads as the page's headline state; the dot is 10 px; the detail line is 14 px.

Responsive behaviour

  • The sentence wraps; it is never truncated, because truncating an error hides the fix.
  • The dot stays aligned with the first line (align-items: center on a one-line sentence; long error sentences wrap beside it).
  • No breakpoint changes. On every width it is the first thing in the first panel (L2-064 reading order: status and verdict first).

Theming

One component token, --status-dot, defaults to --color-fg-subtle. The mock tones set it to --color-accent (busy) or the status -icon tokens. The sentence always uses --color-fg-default, so it reads at full contrast in both themes whatever the tone.

.status--warning { --status-dot: var(--color-warning-icon); }

Accessibility

Role and pattern

A <p role="status" aria-live="polite">: the WAI-ARIA status live region. Only the text node #status-text changes, so the screen reader announces the new sentence once (L2-063). Set B puts aria-live="polite" on the wrapping .stack instead, which also announces the verdict and alerts inside it.

Keyboard

KeyAction
NoneThe status line is not focusable. Tab moves past it to the next control.

Focus

Status changes never move focus. After an error, focus stays on the control the tester used (for example Connect).

Labelling

The sentence is the message; the dot is aria-hidden. The same state is never shown by the dot colour alone (L2-062): “Connected” and “Connection failed” differ in words.

The busy dot is the thinnest margin in the system at 3.15:1 in light; it is decorative, but keep it on --color-bg-surface or lighter.

Motion

The busy dot pulses (opacity 1 → 0.35 over 1.6 s, mocks only). Under prefers-reduced-motion: reduce the shipped rule removes every animation, so the dot is still.

Touch

Not a target.

Content

  • Use the shipped sentences verbatim; the error sentences are fixed by L2 character for character (see Content).
  • Errors name what failed and what to do: “Couldn't connect within 10 seconds. Move closer to the treadmill and try again.”
  • Phases in progress end with an ellipsis character (…), not three dots.
  • Set B shortens the sentence to a label (“Ready”, “Connection failed”) and moves the L2 message into an alert; set A writes its own labels (“Bluetooth is off”). The shipped page puts the L2 message in the status line itself.
