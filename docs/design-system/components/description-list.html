Description list

Term and value pairs for run facts (device, model variant) and verdict facts (meaning, reason, next step).

Overview

A description list (<dl>) pairs a muted term with its value. Stride Link uses two:

  • Run facts (.facts): Device and Model variant under the status line, shown once a device is selected (L2-008 criterion 5).
  • Verdict facts (.verdict__facts): Meaning, optional Reason and Next step inside the verdict card (L2-036, L2-022).

Values are inserted as text nodes only (L2-051): a device name is whatever the treadmill advertises and is untrusted. Telemetry uses its own metric list, not this component.

Anatomy

  1. Term<dt>, muted, body-sm.
  2. Value<dd>, medium weight, wraps anywhere.
  3. GridTwo columns, max-content terms and a flexible value; 8 × 20 px gaps.

Responsive behaviour

  • Run facts keep two columns at 320 px; long names wrap (overflow-wrap: anywhere).
  • Verdict facts stack term over value below 576 px and become two columns from 576 px.

Theming

Terms read --color-fg-muted, values --color-fg-default. Inside the verdict card the background is the verdict tone (--color-success-bg, --color-warning-bg, --color-danger-bg), so both colours are checked against those as well.

Content

  • Terms: Device, Model variant, Meaning, Reason, Next step.
  • Variant values: Standard or Stride 4 on screen; the log records Model variant: standard or Model variant: Stride 4 (L2-008).
  • A device with no name shows (unnamed device) (L2-008 criterion 4).
  • Meaning and next step are the L2-036 strings verbatim; reasons are the L2-022 strings, such as challenge checksum invalid and zero divisor.
