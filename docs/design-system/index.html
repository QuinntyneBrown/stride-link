Start here

Stride Link is one self-contained, offline web page that connects to an Echelon Stride treadmill over Web Bluetooth, runs the init and unlock handshake, and reports one verdict: Silent, Talks, Unlocked or Locked. This system writes down its visual and interaction language once, so the page and any future screen stay consistent.

Two mock sets, no choice yet. docs/mocks holds two overlapping mock sets written by two sessions, and the owner has not yet chosen between them. Set A: pages/start, run, verdict, belt, dialogs/chooser, connection-lost, leave-page and three toast notifications. Set B: pages/stride-link (27 states), dialogs/bluetooth-chooser, notifications/connection-lost and stop-failed. Both share docs/mocks/assets/tokens.css, ui.css and contrast-pairs.json, which is what this system is built on. Every component that appears in either set is documented; neither set's page structure is preferred.

Core components that are not part of this system

The extraction method lists a core set every product usually needs. These have CSS in the shared mock kit (docs/mocks/assets/ui.css) but appear in neither mock set and are not shipped, so documenting them would invent design:

ComponentWhy it does not apply
MenuNo control offers several actions; every action is its own button.
Select, radio group, switch, textareaThe only inputs are two numeric fields and one interlock checkbox (L2-042, L2-046, L2-047).
Combobox, date picker, file upload, sliderNothing on the page picks dates, files or ranges; speed and incline are typed values with a hard cap.
Sidebar navigation, tabs, breadcrumb, paginationStride Link is one page with no routes or sub-views.
TableThe packet log is a role=log list of fixed-format lines (L2-038, L2-039), not tabular data.
TooltipEvery control has a visible text label; nothing is icon-only on the shipped page (L2-063).
Avatar, chip, skeleton, card gridNo people, filters or loading placeholders exist; values show an em dash until decoded (L2-032).

How to use

  1. Link tokens/tokens.css then assets/components.css. In the product they are inlined by scripts/build.ts from src/styles/; keep those files and these in step.
  2. Use the class names from each component's Code section. Never write a raw colour, size, duration or z-index: use a token.
  3. Insert device names, error messages and log text as text nodes only (AGENTS.md); the examples here are static HTML for documentation.
  4. Generate platform constants from tokens/tokens.json (DTCG format; dark values under $extensions).
  5. Check new colour pairings by adding them to tokens/contrast-pairs.json and running check_contrast.py.

Press t or use the theme button to switch themes; ?theme=dark forces one.
