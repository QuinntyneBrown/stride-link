Notifications

Two safety messages interrupt and persist; status changes are polite; toasts are a set A proposal that may only ever add to what the live regions say.

Overview

“Notification” on this page means a message the tester did not ask for. There is no notification centre and no history panel: the packet log already is the history, and nothing persists past the page (L2-052). Notifications fall into three priorities:

When to use

Open decision: toasts. Set A proposes four toast families (export, verdict, belt, stacked). Set B has none, and neither does the shipped page. L2 requires status announcements but not toasts, and every set A toast repeats something a live region already says. If toasts are adopted, they must stay additive:

  • Never the only place a safety message appears; Stop failed and connection lost are never toasts.
  • Never auto-dismiss an error; auto-dismiss others after at least 8 s and pause on hover and focus (WCAG 2.2.1).
  • Sit above the Stop bar (body.has-stop-bar .toast-region), never over it.
  • Do not duplicate the verdict announcement: one polite announcement per change.

Open decision: Stop failed. Set B stacks a full danger alert above Stop belt inside the bar and reserves extra body padding (body.has-stop-alert); the shipped page shows one line of danger text beside the button (.stop-bar__error). Set A shows it as an alert titled “Stop the belt by hand” in the status panel, away from the bar. In every form Stop belt stays enabled and on screen (L2-044).

Responsive behaviour

  • Toast region: full width with 16 px margins below 640 px; 24 rem wide at bottom-right from 640 px; lifted above the Stop bar while it is shown.
  • Stop failed: the shipped error line sits beside the button at every width and wraps inside its own column (the bar's inner row never wraps, so the button narrows); set B's alert takes the full row above the button.
  • Connection lost spans the primary column (shipped) or the viewport (set B banner) at every width.

Accessibility

  • Safety messages are assertive (role="alert"); everything else is polite.
  • Toast dismiss buttons are 44 × 44 px and named Dismiss; actions are real buttons; the toast does not take focus.
  • Toast icons use the --color-*-icon-on-inverse tokens: the plain icon tokens drop to 1.5 to 1.9:1 on the dark theme's paper-coloured toast (design-system fix).
  • Under reduced motion toasts appear and leave without sliding (L2-063).
  • Nothing depends on hover: the pause-on-hover rule also pauses on focus, and no information is hover-only.

Content

  • Safety messages are verbatim L2 and tell the tester what to do physically: the treadmill's stop button or safety key.
  • Toast titles are the event in a few words; the text adds one useful detail (file name, entry count).
  • Use the shipped log wording for verdict changes in lower case with an ASCII arrow (talks -> unlocked); set A's toast title capitalises and uses “→”, which is display copy, not log copy.
