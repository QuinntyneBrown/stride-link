Pattern

Forms

The belt controls are the only form: a safety gate, then apply-on-press numeric commands with a hard 3 km/h cap. Stop never lives inside it.

Overview

Stride Link has exactly one form-like area: the belt controls. It is not a form that is filled in and submitted; it is a set of apply-on-press commands, each of which writes one frame to the treadmill. That changes the usual form rules: there is no submit, no error summary, no autosave and no draft, and every rule bends towards safety.

  • An interlock comes first. Start, speed and incline are not rendered and not focusable until the tester ticks I am standing clear of the belt (L2-042). The checkbox is offered only under a Talks or Unlocked verdict.
  • Each field applies on its own button. Set speed and Set incline validate one value and write one frame, or write nothing and explain why (L2-046, L2-047).
  • The hard cap is a rule, not a hint. Speed above 3 km/h is rejected without writing; the field explains the cap. The cap is never configurable on the page.
  • Stop is not part of the form. It lives in the fixed Stop bar, jumps the write queue and is also sent by Escape from any field.

Text entry, selects, radio groups, switches, multi-step forms and error summaries are not part of this system: no mock in either set and no shipped screen needs them. If a future feature needs one, add the component from the shared kit first and document it here.

There is no busy state on Set speed or Set incline: the write is queued and its result appears in the packet log. Set A's pages/belt/submitting state draws the page unchanged for the same reason.

Responsive behaviour

  • Below 576 px the controls grid is one column: Start, then speed, then incline. Each input stretches and its button keeps its natural width beside it.
  • From 576 px the two fields sit side by side and Start spans both columns.
  • From 992 px the belt panel stays in the left column with the log on the right; nothing else changes.
  • While the belt is active the body reserves the Stop bar height plus --space-2 (shipped), so the incline field is never hidden behind the bar (L2-064).

Accessibility

  • Labels are visible and programmatic: <label for> on each input; the checkbox is wrapped in its label, so the whole row toggles it (L2-063).
  • Help and error text are linked with aria-describedby="speed-help speed-error"; the error has role="alert" and the input aria-invalid="true". The message names the rule and the fix.
  • Hidden controls use the hidden attribute, which the shipped [hidden] { display: none !important } rule keeps out of the Tab order and the accessibility tree (L2-042).
  • When the controls hide, their errors and aria-invalid are cleared (shipped belt-panel.ts); focus stays on the gate checkbox the tester just unticked.
  • Escape inside a number field sends Stop while the belt is active; it is captured on the document before the input sees it (L2-045).
  • Number inputs use inputmode="decimal" for speed and numeric for incline, with min, max and step as hints only: validation happens on press, in code.
  • Every control is at least 44 × 44 px, including the checkbox itself (shipped; the mocks drew a 20 px box inside a 44 px row).
