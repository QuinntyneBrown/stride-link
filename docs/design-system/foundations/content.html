Overview

Stride Link speaks to a tester standing next to a treadmill: short, literal, calm. It says what happened and what to do next, in that order. Every string that L2 fixes is reproduced character for character; the product's message modules (src/ui/messages/*.ts) hold them and must not be reworded.

Voice and tone

  • Plain and specific. “Couldn't connect within 10 seconds.” not “Something went wrong.”
  • Next action included in every failure (L2-058): “Move closer to the treadmill and try again.”
  • Safety first, no drama. Stop and connection-lost messages name the physical fallback: the stop button or safety key.
  • Sentence case for everything; uppercase only through CSS (panel titles, badges).
  • Contractions are fine and used by L2 (can't, doesn't, couldn't).
  • No stack traces on screen; the error name and message go to the log (L2-058).

Labels and buttons

  • Buttons are verbs: Connect, Disconnect, Export log, Start, Set speed, Set incline, Stop belt, Dismiss.
  • Field labels name the value and unit: “Target speed (km/h)”.
  • Help text states the allowed range; the error repeats the rule as an instruction.
  • Device names, error messages and log text come from outside and are inserted as text only (L2-051); never interpolate them into markup.

Usage

  • Change an L2 string only by changing L2 first; then update the messages module and the tests together.
  • Do not paraphrase L2 strings in toasts, tooltips or titles; reuse them or say less.
  • Keep status sentences short enough for one line at 360 px where possible; they wrap cleanly when they don't.

Accessibility

  • Accessible names equal visible labels (L2-063); the Stop button's name is exactly “Stop belt”.
  • Live announcements are full sentences so they make sense heard alone.
  • The em dash for no value is paired with the metric label, so a screen reader hears “Speed, —”; set A also adds visually hidden “No reading yet”.
